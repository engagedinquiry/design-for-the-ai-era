# Design for the AI era

**The design document is the product. The screens are the consequence.**

A method for designing digital experience in an AI era — governed by a document authored before any build exists, not generated by a prompt at the moment someone arrives.

This repo holds two things: the methodology (why this works, and how it's structured) and the spec (the artifact you actually write).

---

## Start here

If you want the argument first — **[docs/methodology.md](docs/methodology.md)**. Ten minutes. Explains why a governed document, not a prompt, is what should precede a build.

If you want the artifact first — **[spec/EXPERIENCE.md](spec/EXPERIENCE.md)**. The actual template. Copy it, fill it in, use it. See **[docs/experience.md](docs/experience.md)** for what this artifact is and why each section exists.

## `docs/` — the methodology

**To make your design document useful, use [EXPERIENCE.md](spec/EXPERIENCE.md).** The docs explain why it's structured the way it is. See [docs/README.md](docs/README.md) for the full reading order.

Each doc adapted from *Design for the AI Era: Paradigm Shift* — provenance noted at the top of the file it came from.

## `spec/` — the artifact

**[EXPERIENCE.md](spec/EXPERIENCE.md)** is the design document itself — not an analogy for it, not one implementation among several. The governing decisions about what an experience should be, for whom, and under what rules, written before a build exists, in a form the build can execute from. Structured around the polygon grammar (named vertices, directed edges, an ambient state) and the five dimensions.

Fork it, copy the skeleton, fill it in for your own system. See [spec/README.md](spec/README.md) for details.
