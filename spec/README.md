# spec/

This folder holds one file: **[EXPERIENCE.md](EXPERIENCE.md)** — the design document itself.

Fork it. Copy the skeleton. Fill it in for your own system.

## What it is

EXPERIENCE.md is the governing decisions about what an experience should be, for whom, and under what rules — written before a build exists, in a form the build can execute from. Structured around a persona grammar (named states, directed edges) and five dimensions (Screen, Context, Content, Time, Trust).

It is not a token file and not a code standard. It is the artifact that holds the actual design decisions — the thing this whole repo is about.

## Before you fill it in

Read **[docs/design-document-is-the-product.md](../docs/design-document-is-the-product.md)** first — a short explanation of what this file is and why each section exists. For the full argument behind the approach, see **[docs/methodology.md](../docs/methodology.md)**.

## Using it with Catenator

EXPERIENCE.md stands on its own — nothing here requires any other tool. If you also want a machine-readable connecting layer linking this document to a token file (`design.md`) or a code standard (`constitution.md`), see **[catenator](https://github.com/engagedinquiry/catenator)**. That's optional, and separate from this repo.
