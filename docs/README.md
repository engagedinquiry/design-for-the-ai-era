# docs/

The methodology behind this repo. Start wherever fits how you read.

**To make your design document useful, use [EXPERIENCE.md](../spec/EXPERIENCE.md).** Everything in this folder explains why it's structured the way it is and how to fill it in. The docs are the argument. EXPERIENCE.md is the artifact you actually use.

## Reading order

| Doc | What it covers |
|---|---|
| [methodology.md](methodology.md) | The core argument. Why a governing document precedes generation, and why AI's role is narrower than most current practice assumes. |
| [experience.md](experience.md) | What EXPERIENCE.md is, specifically — the artifact, what it contains, and how to use it. |
| [polygon-grammar.md](polygon-grammar.md) | How persona is structured — a named space of possible states, with direction-sensitive transitions between them. |
| [dimensions.md](dimensions.md) | The five things a design document governs: Screen, Context, Content, Time, Trust. |
| [prism.md](prism.md) | The delivery mechanism. How a governed document becomes a specific, revealed output for a specific person — without generating anything new at request time. |
| [governance.md](governance.md) | What "governing" means generally, including the local-sensing requirement any implementation needs, without prescribing how. |

Each doc is adapted from *Design for the AI Era: Paradigm Shift* — provenance noted at the top of the file it came from.

## If you only read one thing

Read [experience.md](experience.md), then go fill in [spec/EXPERIENCE.md](../spec/EXPERIENCE.md). The rest of this folder is here when you want the reasoning behind it.
